# Song registration evidence

[CHART_REGISTRATION.md](../../docs/CHART_REGISTRATION.md) documents the startup catalog, registry schema, resource lookup, pack membership, unlocks, menu confirmation and gameplay launch path. It includes proposed local-test hook examples, which were not installed or executed.

`registry_inventory.json` is generated by:

```bash
python tools/song_registry.py
```

It contains all 203 main registry records, typed fields and offsets, four difficulty records per song, exact asset names and existence checks against the extracted asset index, effective defaults, and integration notes/source references. The original binary re-encoded byte for byte and its RSA signature verified. The source SHA-256 and payload/trailer boundaries are retained in the report. The tool reads the registry and asset index and writes only the report.

The VSD registry uses extra-type tag B7 for one-byte booleans. Cross-checking this real usage exposed an incorrect B7=binary64 assumption in the earlier VSB artifacts; those were corrected to GameMaker buffer_bool (type10). All 805 VSB files still parse/re-encode identically, all805 pass real ImHex runtime evaluation, and synthetic boolean coverage was rerun. Their on-disk extra values use only B3/s32 and B6/f32.

This is static code/artifact evidence. Asset-name presence alone is not a runtime audio-payload test, and the supplied custom-entry examples are a proposed implementation boundary rather than a demonstrated in-game mod. No original game data or profiles were changed.
